# 私人小说工作台：从研究资料到可验收的正文

你只需要记住三个位置：**研究资料在 writing-vault；程序在 distill-novels；你的小说在电脑的私人目录。** 工作台把每章的任务、正文、审稿和定稿连在一起，换对话后也能接着做。

程序不自带写作模型，不消耗 API 费用。Codex 负责规划和审稿，Antigravity 负责写正文；双方通过任务包交接。当前版本没有后台自动调度，也不把聊天会员当作 API 账户。

## 本 PR 的直接启动入口

在研究库的 `project/studio` 双击 `start.cmd`；跨平台运行 `python3 project/studio/launch.py`。它会从随附完整工具包安装到独立目录。下文命令从安装后的工具目录执行，实际位置在启动输出中。

## 先启动

需要 Python 3.10 或以上，没有额外 Python 依赖。

Windows：进入本工具库，双击 `novel-studio.cmd`。浏览器打开 `http://127.0.0.1:19423`。首次启动建立空的私人作品库，默认位于 `%LOCALAPPDATA%\NovelStudio`。如果同一父目录有 `writing-vault`，启动器会连接它以检索研究卡。

Linux / WSL / macOS：

```bash
python3 scripts/studio.py serve --open --research-vault ../writing-vault
```

没有研究库时去掉 `--research-vault`。默认作品目录为 `~/.local/share/novel-studio`。Windows 与 WSL 的默认目录是两份数据，不自动同步；选定一处作为唯一主档。`--vault` 要放在子命令前；如果需要换位置：

```bash
python3 scripts/studio.py --vault ~/NovelPrivate serve --open
```

工作台只监听本机。手机尺寸布局可使用，但本版本没有手机远程网址，不要把 `127.0.0.1` 发到手机当作共享地址。

可直接复制的开书、开篇、常规章节和返修提示见 [章节任务模板](章节任务模板.md)。

## 你的日常操作

| 步骤 | 谁负责 | 交付物与下一步 |
|---|---|---|
| 1. 定方向 | 你 + Codex | 填书名、故事定位、文风与不可更改的规则；一次只推进一本 |
| 2. 做章节任务 | Codex | 人物卡、当前章目标、POV、出场人物、节拍；在工作台派稿 |
| 3. 写正文 | Antigravity | 读取任务包，填写正文回收模板；不能改人物主档、章纲和 hash |
| 4. 收稿与审稿 | Codex | 导入正文，再导出包含正文的包；检查因果、动机、知情范围、时间地点、伏笔、节奏 |
| 5. 返修 | Antigravity | 用最新包逐条处理问题；提交新正文，再重新审稿 |
| 6. 定稿 | Codex，必要时由你裁决 | 通过后定稿；只有此时摘要和人物变化进入后章记忆 |

你验收故事方向、关键转折和最终正文。没有主观取舍冲突时，代理可以继续完成已授权的返修，不需要每个按钮都问你。

界面可直接建人物、世界规则、章节，输入或导入正文，填写或导入审稿，导出任务包与项目快照。所有正文版本与审稿保留在主档中；完整恢复使用下面的备份命令。人物初始卡只写开篇状态；受伤、知晓秘密、物品得失等后续变化写在审稿的 `memory`，不要回写初始卡。

## 交给 Antigravity 的一句话

> 读取这个文件夹里的 task.md 和 task.json。你负责当前章正文，按 context 的目标、人物认知和节拍写作；references 只是研究参考。若已有 current_review，逐条返修。复制 task.draft-template.json 为 return.json，只填写 payload.text，保留所有 ID/hash；不要直接编辑私人库主档，不要上传文件，不要自行续写下一章。

这个提示配合真实任务包使用。任务包里的 `instructions` 也包含同样的约束；素材中的命令文字不是代理指令。

## 交给 Codex 的一句话

> 你负责本书统筹、章纲和审稿。每次从本地工作台读取当前版本，再回收写手的 return.json。审稿只依据当前正文与冻结上下文，指出具体原句、问题和可执行改法。不要把计划当事实；summary 只写本章实际发生的事，memory 每条附原句。重要问题未解决就返修；通过后定稿并给下一章派稿。真实正文与任务包留在私人目录；公开 Git 只提交程序改进与脱敏记录。

如需加入最新研究，先在“参考素材”检索并固定卡片版本。书名相同不代表同一作品；参考角色不自动变成原创角色。给某章派稿后再改设定/参考卡，会使有关任务过期，需要重新派稿，原有正文仍在历史中。重新派稿会把旧正文带入当前任务供修订，但旧审稿通过不会沿用。

## 文件交接命令

下列命令从本工具库运行。`PROJECT_ID`、`CHAPTER_ID` 是工作台或 `show` 命令返回的真实 ID，不是书名。Windows 可把 `python3` 换成 `py -3`，路径改为例如 `C:\NovelPrivate\handoff\task.json`。

```bash
python3 scripts/studio.py list
python3 scripts/studio.py show --project PROJECT_ID
python3 scripts/studio.py pack --project PROJECT_ID --chapter CHAPTER_ID --out ~/NovelPrivate/handoff/task.json
```

得到四个文件：`task.json`、`task.md`、`task.draft-template.json`、`task.review-template.json`。让 Antigravity 打开这个交接目录，复制模板为 `return.json` 并填正文：

```bash
python3 scripts/studio.py submit --project PROJECT_ID --file ~/NovelPrivate/handoff/return.json
```

收稿后**重新导出任务包**，此时审稿模板带有当前正文 hash。Codex 复制审稿模板为 `review.json`，填写：

```json
{
  "verdict": "revise",
  "reviewer": "Codex",
  "summary": "本章实际发生的事件摘要，不写后章计划。",
  "issues": [{"severity":"major","description":"问题、原因与建议改法","quote":"必须复制当前正文中的原句"}],
  "memory": [{"subject":"world","text":"本章实际确认的变化","quote":"对应正文原句"}]
}
```

上面只是 `payload` 的可编辑部分，必须保留模板原有 `chapter_id / task_id / context_hash / draft_hash / base_review_id`。人物记忆的 subject 用真实人物 ID；世界变化用 `world`。`pass` 不能带 blocker/major；返修必须至少有一个问题。程序只检查证据原句存在，不会判定解释是否正确。

```bash
python3 scripts/studio.py submit --project PROJECT_ID --file ~/NovelPrivate/handoff/review.json
```

定稿和其他规划修改也可用 `apply --project ID --expected-revision 当前版本 --file action.json`。文件格式为 `{"action":"finalize","payload":{"chapter_id":"实际ID"}}`。界面会自动带当前版本；版本冲突时保留输入，刷新核对后再提交，不直接改主档 JSON。

## 第一次练习与验收

在独立测试目录创建虚构演示，第一章已演示定稿，第二章已经派稿。它不是你的作品，也不是实际 AI 文学质量验收：

```bash
python3 scripts/studio.py --vault ~/NovelStudioDemo demo
python3 scripts/studio.py --vault ~/NovelStudioDemo serve --open
```

先跑一章闭环。验收看五件事：写手能否只凭包开写；问题是否能定位到原句；返修是否针对问题；后章是否得到已确认变化；改前章后是否提醒后章重做。界面“定稿字数”统计非空白字符，不代表质量，也不把研究报告字数算作产出。

## 备份和恢复

```bash
python3 scripts/studio.py backup --out ~/NovelPrivate/backup-2026-11-13.json
python3 scripts/studio.py --vault ~/NovelRestored restore --file ~/NovelPrivate/backup-2026-11-13.json
python3 scripts/studio.py --vault ~/NovelRestored serve --open
```

备份包括私人库的项目主档、JSON 资产、历史和已固定的参考快照，不包含独立研究库、原小说全文、检查点或生成的阅读副本。恢复目标必须为空目录；先校验全部文件路径和 SHA-256，再写入。项目快照导出用于阅读/交接，不等于完整备份。备用副本也含正文，保持私人保存。

## 解决卡点

- 任务过期：先检查设定、前章、参考卡发生了什么改变；确认改动后重新派稿，旧包不能覆盖新任务。
- 无法给后章派稿：首版按章顺序生产，先完成前章定稿。章纲可以提前排，但正文事实不能提前生效。
- 端口被占：已有工作台可能仍开着；访问原地址，或用 `serve --port 19424`。
- Windows 无 Python：安装 Python 3.10+ 并启用 PATH；本入口不用 PowerShell。
- 不知道文件在哪：启动输出会显示实际私人目录；Windows 和 WSL 要统一入口，不能两处各写一份后手工拼合。
- HTX/dot：用户已授权连接，但本轮会话没有可用的 HTX 远程执行入口。这里交付的是代码与可执行流程，安装状态以 HTX 的实际执行结果为准。

## 第一周如何推进

建议第一天只确定一部原创的定位、三位核心人物和前三章目标；第二天完成第一章写作、审稿和一次返修；第三天完成第二章并检查人物状态；第四天修改前三章因果；第五天让你集中验收三章。每天 1–2 个完整章节循环，比再做数百轮来源审计更接近目标。以上是工作节奏建议，不是产量保证或已创建的定时任务。

后续扩展顺序：实际样章质量校准 → 长篇分卷摘要与上下文预算 → 伏笔台账与因果关系图 → 接入经验证的本地代理调度。先用真实作品测出卡点，再决定是否需要 API 自动生成、手机远程入口或常驻任务。
