# 四种可以直接开工的任务

这些是本项目新写的协作提示，不是第三方网站提示词的转载。先读取工作台导出的真实任务包；缺失的书名、人物和定位由项目主档补齐，不靠聊天记忆猜。下面的任务以你当前作品为对象，不会自动调用任何模型。

## 开书：把研究变成一个可写的故事

交给 Codex：

> 读取当前故事定位与我选择的参考卡，只提炼可迁移的结构机制。提出三个原创方案，各用不超过 300 字说明：主角要什么、第一重阻碍、持续冲突来自哪里、人物必须付什么代价、读者为什么愿意继续读、最容易写崩的规则。比较完推荐一个。明确哪些是提案，不要把参考小说的人名、情节和设定直接搬入原创。选择确定后，写入故事定位、三位核心人物初始卡、世界规则和前三章计划；不继续扩大调研范围。

验收：能用一句话说清核心冲突，能列出前三章不同的状态变化。没有这两点，不向写手派稿。

## 开篇：给读者一个具体的承诺

交给 Codex 规划，Antigravity 落文：

> 只规划当前第一章。开场让主角处在具体情境里，尽快显示他想得到什么；让阻力通过动作或对话出现。给出一个本章兑现的小结果，以及一个自然留下的问题。不要先铺满世界百科，也不要为了悬念隐藏 POV 人物本来知道的常识。把开场行动、阻碍、选择、代价、结果分别写成章节节拍；文风服从项目设定。

验收：第一章发生了不可忽略的变化，读者能看见主角的选择；是否采用强钩子由题材与整体节奏决定。

## 常规章节：每章推动一件事

交给 Codex：

> 对照前章定稿摘要，检查这一章要推进的主问题。说明本章目标、为什么此刻行动、对手或环境怎样阻碍、主角怎样选择、得到和失去什么、结尾局面与开头有何不同。检查人物知道的信息是否足以支持其选择。只从有效前章带入事实，把未来计划留在章纲。填入当前章目标与节拍，再派稿。

交给 Antigravity：

> 依据 task.json 写本章，不自增改变全书走向的规则。对话要服务人物目标，描写要改变读者对情境的判断。允许安静章节，但不能没有状态变化。发现任务自相矛盾时返回具体冲突，不能凭空补一个新设定遮住它。将正文写入回收模板的 text。

## 返修：按问题改，避免整章重抽

交给 Antigravity：

> 读取当前稿和最新审稿，先按 blocker、major、minor 排序。修复因果和人物选择，再处理句子。尽量保留已经成立的场景与有效细节；修改某处时检查相邻段落的承接。不要用作者旁白解释一个本应由行动证明的转变。返回完整新正文，保留回收模板版本字段，不覆盖旧文件。

交给 Codex：

> 检查新稿是否解决前一轮每个重要问题，是否引入新的矛盾。每个剩余问题给出原句、判断与改法。通过时摘要只记实际事件，人物/世界变化附原句。不能因为字数增加、语句更华丽或重复审了很多轮就判定质量提高。

这里的产出标准是可写章纲、完整正文、可执行审稿与有效定稿；提示词收藏数量不计产能。
