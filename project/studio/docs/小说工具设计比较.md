# 从现有工具提炼私人创作流程

核对日期：2026-11-13（北京时间）。这是功能思路比较，不是市场份额排名，也不把某个产品的功能宣称当作写作效果实测。

| 代表工具 | 官方功能体现的思路 | 本项目实际采用 |
|---|---|---|
| [Pagekin，原 AI Novel Writer](https://github.com/EthanYoQ/Pagekin) | 同一个作品内连接设定、架构、章节蓝图、正文、审稿、修稿和定稿；本地作品，自备 API 或 Ollama | 单章工作流与状态，稿件和审稿版本绑定；不复制其源码，不重做模型配置平台 |
| [Novelcrafter 的 Progressions](https://www.novelcrafter.com/help/docs/codex/progressions-additions) | 人物变化附着于特定场景，较早场景看不到较晚才发生的变化 | 初始人物卡与定稿后的阶段变化分开；前章记忆按时间进入后章 |
| [NovelAI 的 Lorebook](https://docs.novelai.net/en/text/lorebook/) | 通过触发词把有关设定加入近期上下文，配置条目是否启用 | 按本章出场人物和规则生效章装包；首版用明确选择，未实现自动关键词召回 |
| [星月写作](https://xingyuexiezuo.com/) | 官方公开页面主推提示词库、多模型、拆书、续写/扩写，以及人设、大纲、细纲、开篇等工具箱 | 增加可直接交给代理的开书、开篇、章节推进与返修任务模板；继续由同一个作品主档记录结果，避免工具生成的片段散落 |

这些设计共同解决了“模型写一句很快，但越写越失忆”的问题：需要作品主档、相关上下文、可撤回的修改，以及明确的定稿边界。它们并不能保证文学质量。引用到上下文的设定太多会挤占正文空间，错误摘要也会把矛盾稳定传下去。

你的特殊需求是两个现成代理合作。因此本项目把模型调用与数据管理分开：工作台管版本和记忆，Codex 管规划与审稿，Antigravity 管正文，用户裁决重要取舍。它们交换一个带版本的文件包，无须假设不同聊天窗口互通记忆，也不依赖未经验证的桌面遥控接口。

当前长篇限制也明确保留：上下文带前章摘要和定稿记忆，暂未提供自动分卷压缩；首版按章顺序推进，修改早章后需逐章重新确认。对十万字以上项目，应先用一个短篇/开篇三章验证文风与操作成本，再扩展分卷摘要和伏笔台账。

官方资料只用于核对功能。比较表与实现取舍是本项目的工程判断；没有复制 Pagekin 的 GPL 桌面代码，也没有安装它的 DSH 开发预览插件。

用户补充的 `xingyuexirzuo.com` 未能读取；检索得到对应的“星月写作”域名为 `xingyuexiezuo.com`。功能依据官网的公开搜索索引，直连首页本轮超时；未登录付费区、未实际生成作品。没有足够官方证据验证其内部长期记忆、定稿回写或冲突控制机制，也不采信“百万字不崩”等推广效果承诺。本站提示词和付费内容未被复制。
