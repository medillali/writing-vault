# 小说资料管理与续接

本目录沿用唯一的 `writing-vault`，原书、研究、抽象机制、用户评价与原创作品分别管理。完整JSON是主档，Markdown和剧情图是阅读副本。打开[总目录](README.md)可查看作者顺序、已读范围和下一步。

## 排序与研究队列

失落叶本轮按《网游之纵横天下》→《网游之天下无双》→《斩龙》依序研究。先完成前书，再推进后书；后两书已登记来源不等于已分析。发飙的蜗牛的本地作品按《网游之练级专家》→《贼胆》→《重生之贼行天下》排列，既有《贼胆》研究不因重排而丢弃或重做。

这是当前已提供作品中的相对顺序。作者在其间还创作过其他作品，不能据此宣称三书是连续写成、同一正典或三部曲。顺序依据、证据性质和未提供作品说明见[catalog-config.json](catalog-config.json)。

## 身份与证据

- 一本书沿用一个source_id；文件改名或添加“(1)”不新建作品。内容变化需要新修订，旧修订保留。
- 章节定位结合出现顺序的chapter_id、来源修订和索引指纹。原章号另存，不因重复章号删除正文；合章保持完整阅读单元。若索引被纠正，即使正文哈希未变，也须重新核对章节边界与已有证据；不能只凭文本哈希继续沿用旧映射。
- [reading-units.json](reading-units.json)把正文误识别片段连接回相应章节。现有证据ID不变；阅读和统计使用这一映射，不把“第一节课”“第二回合”等正文句算新章。
- 《练级专家》的“第一回合”误分章已由双书任务在正式索引纠正，当前388段、387个正文/序章阅读单元；本目录已重新对齐。后续既有双书全书任务已完成《练级专家》387单元与《贼胆》463单元的全文九维及终态核验，见[全书入口](../two-books-full-20261025/README.md)；早期试读、旧迁移及其原覆盖范围继续保留，不被新覆盖倒填。
- 角色以“来源＋名称或记录ID＋阶段”区分。同名、同游戏名称和跨书客串不能直接导致人物或世界规则合并。
- 人物的猜测、前世回忆、口头计划和作者附记分别标注。阶段未解不等于结局未解，击杀成功不等于任务成功。
- 同一修订的实际原文用于核实事实。经核源的纠正层优先于旧研究误读；全书终点评定与原卷阶段记录并存。后证可以回答旧疑点，不能让早期人物倒获全知，也不能把研究推断写成原文事实。

## 卡片与使用

人物卡记录目标、限制、关系方向和阶段变化；场景卡记录目标→阻碍→选择→后果；机制卡给出适用条件与失效条件，并固定来源卡版本。所有未审阅研究默认草稿，不替用户收藏或填写审美评价。

本轮失落叶与发飙的蜗牛的卡片统一带 `作者:姓名` 与 `作品:书名` 标签。保留的情终流水旧卡沿用原标签，可从逐书目录或source_id查询。可通过本机 `novel.cmd` 查询：

```bat
novel.cmd search --tag 作者:失落叶
novel.cmd search --tag 作者:发飙的蜗牛 --type scene
novel.cmd search --query 信任
novel.cmd search --source src-2a13958390274509b2af019f6b12d981
```

旧《贼胆》的183份人物材料包含分段观察，不能理解成183个去重人物；60条出场候选保留为候选。剧情线原状态与原阶段同时显示，不自动把分段状态改为全书终点。

其他长篇同样按阶段保存人物材料，同一角色跨卷可以有多张卡。卡片总数用于计算材料规模，去重人物和跨卷变化应查该书人物全弧审计；不能将两种数量混用。阅读旧卡时先查看该书核源纠正和疑点终点账本，再决定是否用于原创练习。

重复蒸馏使用现有 `scripts/library.py asset-put --generated` 并提供当前版本，保护 `user_notes`、`favorite`、`review_status`。研究结论更新保留历史。原创项目通过固定版本引用学习机制，再另写自己的角色、规则和情节。

## 断点与验收

每批保存实际全文读过的章节、证据和下一批起点。未读部分始终在pending中；“全文索引完成”“正文实际阅读完成”“九维研究完成”“用户审阅通过”是不同状态。

继续时先读本目录和该书最新检查点，再阅读原文；不要把自动索引、关键词命中、标题或模型既有印象当成阅读全文。章前材料、卷标题、正文和附记分别计数。

本轮失落叶研究保存到本地资料库，未由本任务提交或推送。蜗牛双书既有任务的远程保存另有独立回执。Git提交与推送需要实际执行后单独报告；没有创建定时续读、Space或ChatGPT记忆同步。原书不进入默认研究备份或Git历史。
